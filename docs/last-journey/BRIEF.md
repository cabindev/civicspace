- เพิ่มลิงก์ใหม่**ถัดจาก `<IssuesMenu />`** ใช้ class เดียวกับลิงก์ "หน้าหลัก" เพื่อให้หน้าตาเหมือนกัน

  ถ้าเจอ peer-dependency error ให้ดูวิธีที่ repo ใช้แก้ไว้ใน commit `fix/npm-peer-deps-next16` ห้ามใส่ `--force` แบบเหมารวม

## 4. โมเดล 3D (หน่วยเป็นเมตร แกน Y ชี้ขึ้น)

สร้างด้วย primitive ของ three ทั้งหมด (`BoxGeometry`, `ExtrudeGeometry`, `PlaneGeometry`) ไม่ต้องโหลด GLB เพื่อให้คุมขนาดไฟล์และทุกชิ้นขยับแยกกันได้
ใช้ `RoundedBoxGeometry` จาก `three/examples/jsm/geometries/RoundedBoxGeometry.js` (radius 0.004) กับชิ้นสีขาว ขอบจะได้ไม่คมเหมือนกล่อง

### 4.0 ข้อมูลจริงจากไฟล์ Blender (`/Applications/MAMP/htdocs/model/white_thai_coffin.blend`)

อ่านจากไฟล์ .blend แล้ว (34 ชิ้นใน collection `COFFIN | editable components.001`) ใช้ค่าตามนี้

- **แปลงแกน**: Blender เป็น Z-up ส่วน three เป็น Y-up ใช้ `three(x, y, z) = blender(x, z, -y)` ค่า y ทุกตัวในเอกสารนี้แปลงแล้ว
- **ตัวหีบใน Blender ทึบ** (`Coffin | white body 199 x 59 x 48 cm` เป็นกล่องเดียว) ต้องสร้างใหม่ให้กลวงตามข้อ 4.1 ห้าม export ตัวนี้ไปใช้ตรงๆ
- ขอบบนตัวหีบอยู่ที่ 0.555 ฐานฝา (`Lid | lower cornice`) อยู่ที่ 0.542 แปลว่าฝาสวมทับขอบ 13 มม. ตอนปิดฝาจึงต้องลงมาครอบ ไม่ใช่วางบนขอบ
- **รูปเทพพนมมีที่ปลาย +X ด้านเดียว** (`Right end | central praying figure` ขนาด 0.29×0.324 ที่ x=0.996, z 0.154–0.478) ปลาย -X มีแค่กรอบขาวกับเส้นทอง ให้ทำแบบเดียวกัน
- ลายข้างใช้รูปเดียวกันทั้งหน้าและหลัง (`Thai ornament | front/back` 1.93×0.451) และเป็นภาพแบน ไม่มี relief เงาทองถูก bake ไว้ในรูปแล้ว
- Material (ค่า linear ให้ใช้ `color.setRGB(r,g,b, LinearSRGBColorSpace)`):
  | ชื่อใน Blender | Base color (linear) | Metallic | Roughness |
  |---|---|---|---|
  | White lacquer | 0.88, 0.90, 0.92 | 0 | 0.32 |
  | Warm decorative gold | 0.65, 0.43, 0.12 | 0.75 | 0.27 |
  | Ornament photo | texture | 0 (ใช้ metalnessMap ตามข้อ 4.1) | 0.52 |
- กล้องใน Blender เป็น orthographic มุม 3/4 จาก (2.5, 2.05, 4.3) ใช้เป็นแนวสำหรับกล้อง A ได้ แต่บนเว็บใช้ perspective
- ไฟล์ถูก save ซ้อนจึงมีของซ้ำ `.001` (material, รูป packed 2 ชุด, README 2 ชุด, collection เปล่า 1 อัน) ไม่มีผลกับงานนี้ ไม่ต้องแก้

### 4.1 หีบศพ: ยึดขนาดจาก Blender (ข้อ 4.0)

ขนาดรวม: ยาว 2.05 × กว้าง 0.65 × สูง 0.60 ด้านยาวอยู่บนแกน X จุดกำเนิดอยู่ที่กึ่งกลางพื้นใต้หีบ

**ตัวหีบ (`body`) ต้องกลวง** เพราะฉากแรกต้องเห็นว่าข้างในว่าง
- ผนัง 4 ด้าน หนา 0.03 สูงจาก y=0.08 ถึง 0.54 และพื้นด้านในที่ y=0.10
- ภายนอกใช้ White lacquer จากข้อ 4.0 ภายในบุผ้าสีครีม `#EFE7DA` (roughness 0.9) ห้ามใส่ร่างหรือหมอน ให้ว่างจริงๆ

**ฐานขั้นบันได 3 ชั้น** (ตาม ref 02): กล่อง 3 ชั้น กว้างลดหลั่น
- (2.05×0.03×0.65 @y0.015), (2.025×0.024×0.63 @y0.042), (2.005×0.026×0.61 @y0.067)
- เส้นลูกปัดทองบางๆ (0.006 สูง, ยื่น 0.002) ที่ขอบบนของแต่ละชั้น

**แผงลายด้านยาว (ทั้งหน้าและหลัง)**: `PlaneGeometry(1.93, 0.45)` ติดห่างผิวหีบ 0.001 ที่ y=0.316 ใช้ `coffin-side.jpg` และตั้งค่า
- `colorSpace = SRGBColorSpace`, `anisotropy = renderer.capabilities.getMaxAnisotropy()` (สูงสุด 8)
- material: `MeshStandardMaterial({ map, roughness:0.45, metalness:0 })` แล้วเพิ่ม `roughnessMap`/`metalnessMap` ที่ได้จากการ threshold สีทองในรูป (เขียนลง canvas: พิกเซลที่ R−B > 0.04 ให้เป็น metal) ทองจะได้สะท้อน env ส่วนพื้นขาวยังด้าน **ข้อนี้คือสิ่งที่ทำให้ลายดูเป็นงานทองจริง ห้ามข้าม**
- กรอบขาวนูนรอบแผง: เสาตั้ง 2 ต้น (0.022×0.47×0.015) และคานนอน 2 เส้น (1.99×0.012×0.015)

**ด้านหัวและท้าย**: กรอบขาวนูนพร้อมเส้นทองบาง (ตาม `create_coffin.py` ส่วน `End |`) ทั้งสองปลาย และติด `coffin-end-figure.jpg` **เฉพาะปลาย +X** กลางด้าน ขนาด 0.29×0.32 (ตอนหมุนในขั้น 2 ปลาย +X จะหันมาทางกล้อง คนดูจึงเห็นเทพพนมขณะหีบเคลื่อนเข้าเตา ส่วนปลาย -X ที่เรียบเข้าเตาก่อน) ใช้ `alphaMap` ที่ได้จากการ threshold แบบเดียวกัน เพื่อให้เห็นเฉพาะตัวทองบนพื้นขาว

**ฝา (`lid`): group แยก มี pivot ที่จุดกึ่งกลางล่างของฝา**
- 3 ชั้นตาม Blender: cornice (2.025×0.022×0.63), rim (2.05×0.024×0.65), top (2.01×0.016×0.61)
- เส้นลูกปัดทองรอบขอบ rim
- ตอนปิดสนิท ฐานฝาอยู่ที่ y = 0.542

**รถเข็นเหล็ก (`cart`)** ตาม ref 04: ถาดเหล็กดำ `#1E1E1E` (metalness 0.6, roughness 0.55) ยาว 2.2 กว้าง 0.72 สูง 0.32 มีล้อ 4 ล้อวิ่งบนราง หีบวางบนรถเข็นตลอดทั้งเรื่อง (ยก body ขึ้น y+0.32) รถเข็นอยู่ใน group เดียวกับหีบเพื่อให้หมุนและเลื่อนไปพร้อมกัน

### 4.2 เตาเผา (เมรุ)

ตั้งเตาบนแกน -Z หน้าประตูอยู่ที่ **z = -4.0** หันหน้าไป +Z

- **ผนัง**: กล่อง 3.4×2.8×0.4 ปูนขาวอมเหลือง `#E8E1D3` มีคราบเขม่าไล่เฉดเหนือช่องประตู (วาดด้วย canvas radial gradient สีดำ alpha 0.55 → 0 ให้เป็น `map` overlay)
- **ช่องประตู**: ช่องโค้งบน กว้าง 0.92 สูง 1.55 ขอบล่างอยู่ที่ y=0.0 ทำด้วย `Shape` แล้ว `ExtrudeGeometry` เป็นกรอบเหล็กหนา 0.06 สีเหล็กดำมีขอบไหม้
- **ด้านในเตา**: กล่องลึก 2.6 (z -4.0 → -6.6) ผนังด้านในเป็นอิฐทนไฟ (canvas texture 512px, อิฐสีครีมเทา ร่องปูนเข้ม) และมี `PointLight` สีส้ม `#FF8A3D` ความเข้มเริ่มที่ 0

## 5. Scroll และ sticky (ห้าม scroll-jacking)

- section หลักสูง **`600svh` บน desktop และ `520svh` บนมือถือ** ข้างในมี `div` แบบ `sticky top-0 h-[100svh]` วาง canvas + overlay
  - ใช้ `svh` ไม่ใช่ `vh` เพื่อไม่ให้ภาพกระตุกตอนแถบที่อยู่ของ Safari/Chrome มือถือหดและขยาย
- progress `target = clamp(-rect.top / (rect.height - innerHeight), 0, 1)` อ่านจาก `getBoundingClientRect()` ใน listener `scroll` แบบ `{ passive: true }`
- ค่าที่ใช้วาด `p += (target - p) * (1 - Math.exp(-dt * 8))` ให้ไหลนุ่มแต่ไม่หน่วงเกิน
- **วาดเฉพาะตอนจำเป็น**: วน `requestAnimationFrame` เฉพาะตอน `|target - p| > 0.0005` หรือมี resize แล้วหยุดเมื่อนิ่ง ประหยัดแบตมือถือ
- หยุด loop เมื่อ section หลุดจอ (`IntersectionObserver`) หรือ `document.hidden`
- ห้ามเปลี่ยนวิธี scroll ของ browser ห้ามใช้ wheel hijack และห้าม `overflow:hidden` บน body ผู้ใช้ต้องเลื่อนผ่านได้เสมอ

### กล้อง (`camera.ts`)

FOV เป็นค่าแนวตั้ง ระยะกล้องต้อง**คำนวณจากความกว้างจอ** เพื่อให้หีบยาว 2.05 ม. ไม่ล้นจอแนวตั้ง

```ts
// ระยะที่ทำให้วัตถุกว้าง w (เมตร) กินพื้นที่ fill (สัดส่วน) ของจอแนวนอน
function fitDistance(w: number, fovDeg: number, aspect: number, fill = 0.86) {
  const hHalf = Math.atan(Math.tan((fovDeg * Math.PI) / 360) * aspect);
  return (w / 2) / Math.tan(hHalf) / fill;
}
```

|---|---|---|
| A · หน้าหีบ | fov 32, มองที่ (0, 0.55, 0), อยู่ที่ (0, 1.6, d) d=max(3.4, fitDistance(2.4)) เงยมองลงประมาณ 20° ให้เห็นข้างในหีบ | fov 40, d=fitDistance(2.3, 40, aspect, 0.9) ยกกล้องขึ้นเพื่อให้หีบอยู่ช่วง 15–55% ของความสูงจอ (ด้านล่างเว้นไว้ให้การ์ดข้อความ) |

- ระหว่างขั้นให้ interpolate ทั้งตำแหน่งและจุดมอง (lerp ทั้งสองค่า แล้ว `lookAt`) ห้าม lerp quaternion ตรงๆ เพราะกล้องจะส่าย

## 7. Overlay ข้อความ (จาก `content.ts`)

ข้อความทุกชิ้นเป็น DOM จริง (ไม่วาดลง canvas) คนใช้ screen reader อ่านได้ตามลำดับ และค้นหาด้วย Ctrl+F ได้

- **Desktop**: การ์ดอยู่ซ้ายกลางจอ กว้าง 380px
- **Mobile**: การ์ดอยู่ล่างจอ `bottom: max(16px, env(safe-area-inset-bottom))` ซ้ายขวา 16px สูงไม่เกิน 38svh พื้นขาวโปร่ง 88% + `backdrop-blur` ตัวอักษร**อย่างน้อย 15px** (เว็บนี้ปกติตัวเล็ก แต่ข้อความทับภาพ 3D ต้องอ่านง่ายกว่า)
- ช่วงท้าย (ขั้น 3–5) ฉากมืด การ์ดเปลี่ยนเป็นพื้นถ่าน `#1C1917/90%` ตัวอักษรครีม `#FEF3C7` ต้องผ่าน contrast 4.5:1 ทั้งสองแบบ
- การ์ดแต่ละใบ fade + เลื่อนขึ้น 12px ในช่วง 12% แรกของขั้น และ fade ออกใน 12% สุดท้าย (ใช้ framer-motion หรือ CSS ก็ได้ แต่ต้องขับด้วย p ตัวเดียวกับ 3D)
- **จุดบอกขั้น**: 6 จุดด้านขวา (มือถืออยู่บนสุดของการ์ด) กดแล้ว `window.scrollTo` ไปจุดเริ่มของขั้นนั้น (`behavior: 'smooth'` ยกเว้น reduced-motion) แต่ละจุดเป็น `<button>` มี `aria-label` = ชื่อขั้น
- ขั้น 0 มีคำบอก "เลื่อนลงช้าๆ" พร้อมลูกศรขยับเบาๆ หายไปเมื่อ p > 0.03
- ปุ่ม "ข้ามไปอ่านเนื้อหา" (skip link) ที่มุมบน โฟกัสด้วยคีย์บอร์ดได้ เลื่อนไปที่ `#learn`

6. ลิงก์ต่อไป `/issues/life-rituals` และบทความหมวดงานศพ (category id **16** ใน `app/lib/issues.ts`) ใช้ helper ดึงบทความที่หน้า issues ใช้อยู่ ห้ามเขียน fetch ใหม่ซ้ำ

## 9. Mobile, performance และการเข้าถึง (ห้ามตัด)

| เรื่อง | กติกา |
|---|---|
| DPR | `Math.min(devicePixelRatio, isMobile ? 1.5 : 2)` ถ้าเฉลี่ย 30 เฟรมช้ากว่า 24ms ให้ลดเป็น 1 อัตโนมัติ |
| Draw calls | ไม่เกิน ~90 รวมชิ้นสีขาวที่ material เดียวกันด้วย `BufferGeometryUtils.mergeGeometries` |
| Texture | ไม่เกิน 1024px, canvas texture 512px, เปิด mipmaps |
| โหลด | `JourneyCanvas` ใช้ `next/dynamic` แบบ `ssr:false` ระหว่างโหลดให้แสดง `fallback-coffin.png` (ใช้ `next/image` + `priority`) แล้ว crossfade เป็น canvas เมื่อ render เฟรมแรกเสร็จ จะได้ไม่มีจอว่าง |
| ไม่มี WebGL / context lost | แสดง `JourneyFallback` คือรูป fallback + ข้อความ 6 ขั้นเรียงลงแบบปกติ |
| `prefers-reduced-motion` | ยัง render 3D ได้แต่**ไม่ interpolate** ให้ snap ไปท่าสุดท้ายของขั้นปัจจุบันพร้อม crossfade 200ms ไม่มีกล้องเคลื่อน ไม่มีลูกศรเด้ง |
| Resize/rotate | debounce 150ms คำนวณกล้องใหม่ทุกครั้ง ใช้ `ResizeObserver` บน container ไม่ใช้ `window.resize` อย่างเดียว |
| Cleanup | unmount ต้อง dispose geometry/material/texture/renderer, ยกเลิก RAF, ถอด listener ทุกตัว (เปลี่ยนหน้าไปมาแล้ว memory ต้องไม่โต) |
| Touch | canvas ต้อง `pointer-events: none` นิ้วที่ปัดบนภาพต้องเลื่อนหน้าได้ปกติ |
| Canvas a11y | `role="img"` + `aria-label` บรรยายขั้นปัจจุบัน เช่น "หีบศพสีขาวลายทองกำลังปิดฝา" |
| เสียง | ไม่มีเสียง |

## 10. โทนและความเหมาะสม (สำคัญ)

หน้านี้พูดถึงความตาย คนที่เข้ามาอาจเพิ่งเสียคนที่รัก

- **ห้ามมีร่าง ไฟลุก ควัน เถ้า หรือ particle เปลวไฟ** สิ่งที่บอกว่ามีไฟมีแค่แสงอุ่นจางๆ ในช่องมองตอนท้าย
- จังหวะช้า นุ่ม ไม่มี bounce แบบการ์ตูน (settle ของฝา 3 มม. คือมากที่สุดที่ทำได้)
- ใช้สีขาว ทอง และถ่านเท่านั้น ไม่ใช้เหลืองสดของเว็บในฉาก 3D (สีเหลืองใช้ได้ใน UI ด้านล่าง)
- น้ำเสียงข้อความชวนเจ้าภาพตัดสินใจเอง **ไม่ตำหนิประเพณี** (บทเรียนจากคอมเมนต์ "อยู่ที่เจ้าภาพ ไม่ใช่ประเพณี" ที่ได้ 792 ไลก์)
- ตราเทพพนมเป็นของศักดิ์สิทธิ์ ห้ามบิด ยืด หรือตัดครึ่ง
